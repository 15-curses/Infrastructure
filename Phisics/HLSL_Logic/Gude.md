## 1)  Start MoveKernels:

CPU вызывает диспетчеризацию (dispatch) для вычислических
шейдеров (кернелов), отвечающих за перемещение объектов.
Количество рабочих групп (thread groups) для каждого кернела
рассчитывается путем округления числа обрабатываемых
им объектов до ближайшего большего числа, кратного 32 (размер развертки/варпа). 
Параллельно CPU подсчитывает суммарное количество объектов,
перемещаемых всеми кернелами вместе. Это общее число также
округляется до ближайшего кратного 32 и делится на 32.
Полученное значение (количество необходимых групп) записывается
в нулевой слот ([0]) буфера MovedObjectCounter. Оно будет использовано 
на этапе [MortonKernel](#3-mortonkernel) для непрямого вызова (DispatchIndirect) шейдера Morton.

## 2) MoveKernels:

Каждый вычислительный шейдер (kernel) по собственной математической
модели рассчитывает новую позицию объекта, а также его линейную и угловую скорости.
После этого данные обо всех перемещенных объектах записываются в буфер MovedObjects.
Индексация в буфере реализуется через атомарный счетчик InterlockedAdd.

Запись производится в следующем формате:

```hlsl
struct Obj {
    AABB bound; // Ограничивающий объем объекта (задан min и max координатами по X, Y, Z)
    uint objId; // Индекс в глобальном буфере объектов (модифицируется только на стороне CPU)
};
```


## 3) MortonKernel
Каждый поток вычисляет свой глобальный индекс через семантику SV_DispatchThreadID. 
По этому индексу поток считывает данные объекта (его AABB) из буфера MovedObjects, заполненного на предыдущем этапе.
Далее для каждого объекта выполняются следующие операции:

1. Вычисление центра AABB: Находится средняя точка между минимальной (min) и максимальной (max) координатами объекта:
   $$\text{Center} = (\text{min} + \text{max}) \times 0.5$$

2.  Генерация кода Мортона: Полученные нормализованные 3D-координаты центра передаются в алгоритм Мортона(как работает алгаритм можно прочитать в пункте [Алгоритм Мортона (Z-кривая)](#алгоритм-мортона-z-кривая)) для расчета одномерного индекса
(Morton code), который будет использоваться для пространственного упорядочивания объектов в пункте 4.

3. Запись в буфер: Результат записывается в буфер Out_MortonPairs в формате следующей структуры:
```hlsl
struct MortonPair {
    uint mortonCode; // Рассчитанный код Мортона
    uint objectID;   // Исходный глобальный индекс объекта
};
```

## 6) BVH Traversal (Обход дерева)

Процесс обхода иерархии ограничивающих объемов реализован в Compute Shader и устроен следующим образом:

1. **Идентификация потока:**  
   Каждый поток вычисляет свой уникальный глобальный индекс в пространстве вычислений через семантику `SV_DispatchThreadID.x`. Этот индекс соответствует конкретному объекту (листу дерева), для которого ищется коллизия.

2. **Подготовка данных:**  
   По полученному индексу поток извлекает из буфера `In_BVHNodes` исходные данные «своего» объекта:
   1) Ограничивающий бокс (**AABB**).
   2) Идентификатор объекта (**ID**), который на уровне листьев временно хранится в поле `leftChild`.

3. **Запуск Broad-Phase поиска:**  
   Используя подготовленные данные, поток запускает [алгоритм параллельного обхода дерева BVH (Broad-Phase)](#алгоритм-параллельного-обхода-дерева-bvh-broad-phase). В качестве структуры данных для поиска пересечений выступает тот же буфер `In_BVHNodes`, начиная с корневой ноды.

## Алгоритм Мортона (Z-кривая)

Процесс генерации 30-битного кода Мортона из мировых координат центра объекта состоит из четырех последовательных этапов:

1. Нормализация координат сцены
* Из мировых координат центра объекта вычитается минимальная точка сцены (SceneMin).
   * Результат умножается на SceneInvSize (обратный размер сцены, рассчитанный на CPU как $\frac{1}{\text{SceneMax} - \text{SceneMin}}$).
   * Этот шаг приводит координаты объекта к строгому диапазону [0.0, 1.0] относительно глобальных границ всей сцены. Данные о размерах сцены берутся из буфера параметров SceneBounds.
2. Масштабирование и защита от переполнения (Clamp)
* Полученные нормализованные значения умножаются на 1024.0f и приводятся к целочисленному типу (uint).
   * С помощью функций ограничения (min/max) координаты принудительно зажимаются в диапазоне от 0 до 1023. Это гарантирует, что координата по каждой из трех осей займет ровно 10 бит в памяти, что предотвращает выход за границы координатной сетки 1024³ и порчу данных на следующих этапах.
3. Параллельное «раздвигание» битов
* Каждое 10-битное число обрабатывается специальной функцией для создания «пустот» под биты других осей. Она преобразует сплошной ряд битов вида abcdefghij в разреженную строку вида _**a00b00c00d00e00f00g00h00i00j**_ (где между каждым значащим битом остаются два пустых нуля).
   * Для достижения максимальной скорости на GPU этот процесс реализован без медленных циклов: вместо них используются математические операции умножения на фиксированные «магические числа» и побитовые маски И (&).
4. Сборка кода через перемежение битов (Interleaving)
* Разреженные цепочки битов каждой оси сдвигаются влево на фиксированный шаг, чтобы занять свои уникальные позиции в итоговом регистре:

  1) Координата X остается на месте (без сдвига).
  2) Координата Y смещается влево на 1 бит.
  3) Координата Z смещается влево на 2 бита.

  Все три смещенные цепочки объединяются с помощью побитового ИЛИ (|). На выходе получается единый 30-битный код Мортона, в котором биты чередуются по паттерну фрактальной Z-кривой: ... Z Y X Z Y X.

#### Итог: Сгенерированный код вместе с исходным ID объекта записывается в буфер пар, который далее передается на этап сортировки.

## Алгоритм параллельного обхода дерева BVH (Broad-Phase)

**Цель:** Быстро найти все пересекающиеся пары объектов, избегая проверки «каждый с каждым» (сокращение сложности с $O(N^2)$ до $O(N \log N)$).

#### Как это работает:
1. **Распараллеливание:** Видеокарта запускает отдельный поток для каждого объекта (листа дерева). Каждый поток ищет столкновения только для своего объекта.
2. **Инициализация:** Поток берет ограничивающий бокс (AABB) своего объекта и кладет в локальный стек индекс корня дерева (самую большую коробку).
3. **Цикл обхода (пока стек не пуст):**
   1) **Извлечение:** Поток достает из стека индекс узла и читает его данные.
   2) **Грубая отсечка (AABB Тест):** Если бокс узла **не пересекается** с боксом нашего объекта, поток отбрасывает этот узел и всю его ветку (`continue`).
   3) **Если узел — Ветка:** Поток берет индексы левого и правого «ребенка» этой ветки и записывает их в стек для проверки на следующих шагах.
   4) **Если узел — Лист (другой объект):** Поток проверяет пересечение геометрии. Чтобы избежать дубликатов (не проверять пару $A \leftrightarrow B$ дважды), столкновение регистрируется только если ID текущего объекта меньше ID найденного.
4. **Завершение:** Когда стек пустеет, поток завершает работу.
